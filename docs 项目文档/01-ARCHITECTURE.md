### 三轨制对比

| 维度 | 全自动 (A) | 手动 (B) | Seed (C) |
|------|-----------|---------|----------|
| **输入** | URL | 标题/方向 | 种子关键词 |
| **问答** | 1-2 个 | 5 步 | 3 个 |
| **输出** | 1 篇文章 | 1 篇文章 | 2 个选题方向 |
| **DataForSEO** | 自动 | 强制展示 | 代表性验证 |
| **成本** | ~$1.54 | ~$1.54 | ~$0.47 |

### 自动化程度

| 层级 | 自动化程度 | 人工参与 |
|------|-----------|---------|
| 输入层 | 手动触发/自然语言 | 选择输入源或直接描述需求 |
| **SmartLauncher v2.1** | **三轨制** | **全自动: 1-2 问题 / 手动: 5 步 / Seed: 3 问题** |
| 处理层 | Agent 自主 | 仅 3 轮后仍 <75 分时介入 |
| 竞品验证层 | Agent 自主 | 无（自动 PASS/FAIL） |
| 输出层 | 手动确认 | 中文预览 + 发布确认 |

## 各层职责

### Layer 1: 知识层 (Knowledge Foundation)

**职责**: 存储和提供可复用的知识、规范、工具调用能力

**组成**:
- 共用 Skills：所有生产线共享的基础能力
- 专用 Skills：各生产线特有的能力

**特点**:
- 无状态，被调用时激活
- 可组合，Skills 之间可相互引用
- 可版本化，支持迭代更新

### Layer 2: 调度层 (Orchestration)

**职责**: 协调 Skills 和 Agents，驱动生产流程

**组成**:
- Scout Agent：上游内容侦察
- Filter Skills：内容筛选
- Create Skills：内容生产
- Publish Skills：内容发布
- Monitor Agent：数据监测
- Feedback Skills：反馈分析

**特点**:
- 闭环设计，反馈驱动优化
- 人工节点最小化
- 异常自动上报

### Layer 3: 管理层 (Control Plane)

**职责**: 提供可视化监控和人工决策界面

**组成**:
- 上游雷达：内容发现监控
- 进度看板：生产进度跟踪
- 数据仪表盘：效果分析展示

**特点**:
- 人工确认入口
- 异常处理界面
- 数据洞察展示

## 节点类型说明

| 节点 | 形态 | 说明 |
|------|------|------|
| 1. Trigger | 定时任务 | 触发生产流程，可定时/手动/事件驱动 |
| 2. Scout | **Agent** | 持续监控上游内容源 |
| 3. Filter | Skill | 按规则筛选内容 |
| 4. Approve | **人工** | 选题确认，战略决策 |
| 5. Plan | Skill | 生成生产计划 |
| 6. Create | Skill 组合 | 调用多个 Skills 生成内容 |
| 7. QA | Skill | 质量检查（AEO 评分等） |
| 8. Review | **人工** | 最终发布前审核 |
| 9. Publish | Skill | 发布到 Framer CMS |
| 10. Monitor | **Agent** | 持续监测发布后数据 |
| 11. Feedback | Skill | 分析数据，生成反馈 |

## 人工节点设计

整个闭环只保留 **2 个人工节点**：

| 节点 | 决策内容 | 预期耗时 |
|------|----------|----------|
| **选题确认** | 确认侦察到的内容是否值得生产 | 5-10 分钟/批次 |
| **发布审核** | 确认最终内容质量可以发布 | 10-15 分钟/篇 |

## 异常上报机制

```
自动流转 + 异常上报

正常情况：
Scout → Filter → [等待确认] → Plan → Create → QA → [等待审核] → Publish → Monitor

异常情况（自动上报到 Slack）：
├── QA 分数 < 60 → 上报，暂停流程
├── 图片生成失败 → 上报，人工决策
├── 格式转换错误 → 上报，人工修复
└── 发布失败 → 上报，人工排查
```

## SmartLauncher 三轨制设计 (v2.8)

### SmartLauncher v2.1 工作流

```
用户输入 (任意形式)
       ↓
┌─────────────────────────────────────┐
│  SmartLauncher v2.1                  │
│  Phase 0: 模式选择                   │
│  ┌─────────────────────────────────┐│
│  │ [A] 全自动模式                  ││
│  │ [B] 手动模式                    ││
│  │ [C] Seed 模式                   ││
│  └─────────────────────────────────┘│
└──────────────┬──────────────────────┘
               ↓
    ┌──────────┼──────────┐
    ↓          ↓          ↓
 Track A    Track B    Track C
 全自动      手动       Seed
```

### Track A: 全自动路线

```
用户: "https://competitor.com/blog/ai-video"
       ↓
┌─────────────────────────────────────┐
│  全自动模式                          │
│  ├─ 问题 1: 目标读者                 │
│  └─ 问题 2: 产品植入层级             │
└──────────────┬──────────────────────┘
               ↓
═══════════════════════════════════════
▶ 一口气执行到 Preview
═══════════════════════════════════════
Scout → Writer → Editor → AEO → Framer → Preview
```

### Track B: 手动路线

```
用户: "帮我写一篇 Kling vs Runway 对比"
       ↓
┌─────────────────────────────────────┐
│  手动模式 (5 步确认)                  │
│  ├─ Step 1: 内容类型选择             │
│  ├─ Step 2: DataForSEO 数据确认      │
│  ├─ Step 3: Writer 路由选择          │
│  ├─ Step 4: 标题选择 (5+ 选项)       │
│  └─ Step 5: 配置摘要确认             │
└──────────────┬──────────────────────┘
               ↓
═══════════════════════════════════════
▶ 确认后全自动执行
═══════════════════════════════════════
Writer → Editor → AEO → Improver → Framer
```

### Track C: Seed 路线 (选题漏斗)

```
用户: "帮我找选题，种子词是 AI video"
       ↓
┌─────────────────────────────────────┐
│  Seed Mode (6 Phase 漏斗)            │
│  ├─ Phase 0: Mission Config          │
│  ├─ Phase 0.5: 竞品意图发现          │
│  ├─ Phase 1: 意图扩散 → 60-80 关键词 │
│  ├─ Phase 2: DataForSEO 验证         │
│  ├─ Phase 2.5: Scope 裁剪 → 10 方向  │
│  └─ Phase 3: Title Lock → 2 选题     │
└──────────────┬──────────────────────┘
               ↓
输出: 2 个 Direction 对象
用户: "写 D01" → 执行 Writer 流程
```

## 批量处理设计 (v2.3 NEW)

### batch-processor 工作流

```
输入: [URL1, URL2, URL3, ...]
       ↓
┌─────────────────────────────────────┐
│  batch-processor                     │
│  ├─ 1. 创建 batch-{date}-{id} 目录   │
│  ├─ 2. 生成 00-batch-manifest.json   │
│  ├─ 3. 队列执行 (依次/并行)          │
│  ├─ 4. 实时更新状态                  │
│  └─ 5. 生成 00-batch-summary.md      │
└─────────────────────────────────────┘
```

### 输出目录结构

```
/reports/batch-YYYY-MM-DD-{id}/
├── 00-batch-manifest.json    # 批量任务清单
├── 00-batch-summary.md       # 汇总报告
├── YYYY-MM-DD-{topic-1}/     # URL1 输出
├── YYYY-MM-DD-{topic-2}/     # URL2 输出
└── YYYY-MM-DD-{topic-3}/     # URL3 输出
```

### 执行模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **依次执行** (默认) | URL1 → URL2 → URL3 | 更稳定，便于追踪 |
| **并行执行** | 同时 2-3 个 | 更快，需注意 API 限流 |
