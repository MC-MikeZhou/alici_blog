## 一、Claude 行为问题

### 问题 1: Claude 进入死循环

**症状**:
- 反复尝试同一方法，每次都失败
- 不断道歉但不改变策略
- 输出越来越长但问题不解决

**解决步骤**:
1. `/clear` 清除当前上下文
2. 简化任务到最小可行单元
3. 给一个最小示例："这是输出应该的样子：[示例]"
4. 如果还不行，换个角度表述任务

**预防**:
- 一次只给一个明确任务
- 任务描述要具体，避免模糊指令

---

### 问题 2: 输出质量突然下降

**症状**:
- 前面输出还好，后面开始跑偏
- 开始产生重复内容
- 忽略之前的指令

**原因**: 通常是上下文使用超过 30%

**解决步骤**:
1. 检查上下文使用率（如果有显示）
2. `/compact` 压缩上下文
3. 复制关键信息到剪贴板
4. `/clear` 清除
5. 粘贴关键信息，重新开始

**预防**:
- 养成习惯：复杂任务拆分为多个会话
- 定期使用 `/compact`

---

### 问题 3: Claude 不按指令执行

**症状**:
- 明明说了不要做某事，但还是做了
- 输出格式与要求不符
- 跳过了某些步骤

**解决步骤**:
1. 检查 CLAUDE.md 是否有冲突指令
2. 将关键指令加粗或放在开头
3. 使用 "你必须..." 或 "禁止..." 等强调词
4. 在指令中说明原因（为什么不能这样做）

**预防**:
- 定期清理 CLAUDE.md 中过时的指令
- 保持指令简洁，避免互相矛盾

## 二、AEO 评分问题

### 问题 4: AEO 分数卡在 70 左右

**症状**: 多次 `/improve-article` 仍无法突破 75 分

**检查清单**:
- [ ] 开篇 40-60 词直接回答标题问题？
- [ ] 有 FAQ 章节（3-5 个问题）？
- [ ] 每个 FAQ 答案独立可引用（不依赖上下文）？
- [ ] 无营销词（revolutionary, game-changing, cutting-edge）？
- [ ] 有具体数据点（数字、百分比、时间）？
- [ ] 结构清晰（H2/H3 层级分明）？

**快速修复**:
```markdown
# 开篇模板
[直接回答标题问题，40-60词]

# FAQ 模板
## Frequently Asked Questions

### Q1: [具体问题]?
[独立可引用的答案，30-50词]

### Q2: [具体问题]?
[独立可引用的答案，30-50词]
```

---

### 问题 5: AEO 评分波动大

**症状**: 同一篇文章评分结果不一致

**原因**: AEO 评分有一定主观性，不同会话可能有轻微差异

**解决**:
1. 连续运行 3 次 `/analyze-aeo`
2. 取中位数作为参考
3. 关注具体扣分项而非总分

## 三、图片生成问题

### 问题 6: FAL.ai 调用失败

**症状**: Editor Skill 生成图片时报错

**检查步骤**:
1. API Key 是否有效
2. 账户余额是否充足（单张约 $0.15）
3. 网络连接是否正常

**手动测试**:
```bash
python /scripts/fal_image_generator.py --prompt "test image" --output test.png
```

---

### 问题 7: 图片上传失败

**症状**: 图片生成成功但上传 CDN 失败

**检查步骤**:
1. SSH 连接测试: `ssh root@<YOUR_SERVER_IP>`
2. 目标目录权限: `/var/www/static/static/image/other/gen_images/`
3. 磁盘空间: `df -h`

**手动上传**:
```bash
rsync -avz /local/path/image.png root@<YOUR_SERVER_IP>:/var/www/static/static/image/other/gen_images/
```

---

### 问题 8: 图片 URL 404

**症状**: CDN URL 返回 404

**检查**:
1. 确认文件已上传到正确路径
2. 确认文件名大小写一致
3. URL 格式: `https://ct2.alici.ai/static/image/other/gen_images/[filename]`

## 四、工作流问题

### 问题 9: 会话中断后不知道从哪继续

**解决**:
1. 进入项目目录: `/reports/[日期]-[主题]/`
2. 读取 `00-implementation.md`
3. 找到 `## Current Phase` 或最后更新的内容
4. 运行对应的下一个斜杠命令

**示例**:
```markdown
# 如果 00-implementation.md 显示:
## Phase 3: AEO Analysis ✅
## Phase 4: Improvement ⏳ (in progress)

# 那么继续运行:
/improve-article /reports/xxx/03-article-edited.md
```

---

### 问题 10: /full-workflow 中途失败

**症状**: 完整工作流执行到某一步停止

**解决**:
1. 不要重新运行 `/full-workflow`（会覆盖已有进度）
2. 查看 `00-implementation.md` 确认中断点
3. 手动运行后续的单个命令

---

## 五、内容质量问题

### 问题 11: 文章内容跑偏

**症状**: 生成的内容与预期主题不符

**原因**:
- Topic Brief 不够清晰
- 输入素材质量差
- 指令不够具体

**解决**:
1. 重新运行 `/scout-topic` 生成更好的 Brief
2. 检查输入 URL 是否有效
3. 在写作命令中添加具体约束

---

### 问题 12: 生成的文章太短/太长

**标准**:
- Tutorial: 1,800-2,500 词
- List: 2,000-3,000 词
- News: 1,200-1,800 词

**解决**:
- 太短: 要求补充具体章节
- 太长: 要求精简，保留核心内容

---

## 六、MCP 问题

### 问题 13: DataForSEO MCP 连接失败

**症状**: 选题分析时无法获取 SEO 数据

**检查**:
1. `.mcp.json` 配置是否正确
2. API 凭证是否有效
3. 模块是否启用 (SERP, KEYWORDS_DATA)

**备用方案**:
不使用 SEO 数据，基于竞品内容分析进行选题
