# Agent Team Scout: 多角色团队选题研究系统

> **版本**: v1.1 概念设计 (PRD 吸收版)
> **日期**: 2026-02-06
> **状态**: 策划阶段（尚未实现）
> **受众**: 团队成员（非技术向）

---

## 一句话说明

让 6-8 个"虚拟专家"同时从不同角度研究同一个领域。每个专家自己验证数据、分析竞品，总管只做战略决策（去重、排序、拍板）— 而不是从头验证每个人的工作。

---

## 为什么需要团队研究？

### 当前做法的问题

目前我们使用 `growth-topic-scout`（单 Agent）做选题研究。它的能力很强，但有一个本质局限：**一个人只有一个视角**。

1. **视角单一** — 一个 Agent 研究选题，不管提示词写得多好，思维模式都是线性的
2. **锚定效应** — 找到第一个有潜力的方向后，后续思考被"锚定"在那个方向附近，多样性不足
3. **证据维度单一** — 关键词工具只看搜索量，缺少市场趋势、品牌适配、用户画像等视角

### 对比：单人 vs 团队

| 维度 | 当前 (单 Agent Scout) | 新方案 (Team Scout) |
|------|---------------------|-------------------|
| 视角数量 | 1 个 | 6-8 个 |
| 选题多样性 | 靠算法去重 | 天然分化（每人看不同角度）|
| 证据丰富度 | 仅关键词数据 | 关键词 + 市场 + 品牌 + 用户画像 |
| 数据验证 | 集中验证 (总管做) | 分布式验证 (每人自己验证) + 总管抽查 |
| 创作者分群 | 无 | 2-4 个 Persona（不同用户群视角）|
| 每次产出 | 2-3 个方向 | 5-10 个方向 |
| 并行效率 | 串行思考 | 6-8 人同时工作 |

### 类比：编辑部选题会

传统媒体的编辑部选题会，通常有 5-8 个不同角色的编辑各自提出选题，然后主编综合筛选。Team Scout 就是这个过程的数字化版本：

```
传统编辑部选题会:
  记者 A (流量) + 编辑 B (内容) + 分析师 C (市场) + ... → 主编汇总

Agent Team Scout:
  研究员 (关键词) + 主编 (内容) + 分析员 (市场) + ... → 总管汇总
```

## 团队成员介绍

### 固定成员（每次必有）

| 角色 | 职责 | 关注什么 |
|------|------|---------|
| **选题研究员** | 搜索量驱动，找流量机会 | "这个词月搜索量多少？趋势是涨还是跌？" |
| **内容主编** | 评估内容类型，发现竞品空白 | "竞品写了什么？哪种格式最有效？哪里是空白？" |
| **市场分析员** | 市场数据，趋势报告，行业动态 | "这个市场多大？增速如何？有什么新事件？" |

### 按需成员（智能推荐）

| 角色 | 何时加入 | 关注什么 |
|------|---------|---------|
| **Prompt 工程师** | 种子词涉及技术/AI 工具 | "用户需要什么提示词？工作流怎么优化？" |
| **品牌专家** | 种子词涉及营销/品牌/广告 | "alici.ai 的哪个产品能关联？CTA 怎么设计？" |
| **创作者 Persona** (2-4个) | 始终推荐 2 个，Deep 模式 3-4 个 | "如果我是这类用户，我会搜什么？" |

### 智能推荐如何工作

不需要你手动选择 Agent 阵容。系统会根据你输入的种子词自动分析领域特征，推荐合适的团队成员：

```
输入种子词 (如 "AI UGC Ads")
         ↓
系统分析领域特征:
  - 涉及技术？ → 推荐 Prompt 工程师
  - 涉及营销？ → 推荐品牌专家
  - 用户群特征？ → 推荐 2-3 个 Persona
         ↓
展示推荐阵容 (你可以调整)
         ↓
确认后开始研究
```

你可以：
- 接受推荐阵容（推荐）
- 取消某个成员
- 添加自定义角色

### 创作者 Persona 示例

以 **AI UGC Ads** 领域为例，系统可能推荐这些创作者视角：

| Persona | 特征 | 搜索习惯 |
|---------|------|---------|
| **大学生创作者** | 零预算、手机优先、时间充裕 | "how to make money with AI", "free AI tools" |
| **专业创作者** | 有经验、关注效率、付费意愿强 | "best UGC tools", "AI video workflow" |
| **小企业主** | 想降本、不懂技术、看 ROI | "AI ads for small business", "reduce ad cost" |
| **AI 创业者** | 技术背景、关注产业趋势 | "UGC market size", "AI ad tech stack" |

> 注意：Persona 不是硬编码的。换一个领域（如 "AI headshots"），系统会推荐完全不同的 Persona 组合。

## 工作流程

### 4 步走

```
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│   Step 0         │    │   Step 1         │    │   Step 2         │    │   Step 3         │
│   任务说明       │ →  │   团队并行研究   │ →  │   总管决策       │ →  │   补充验证       │
│                  │    │   + 数据自验证   │    │   (CEO 模式)     │    │                  │
│ · 输入种子词     │    │ · 每人独立工作   │    │ · 去重合并       │    │ · 补充未验证数据 │
│ · 确认 Agent 阵容│    │ · 5-8 个选题/人  │    │ · 相似度分析     │    │ · SERP 分析      │
│ · 选研究深度     │    │ · 每人自查数据   │    │ · 覆盖度检查     │    │ · AEO 评分       │
│ · 冻结研究合同   │    │ · ~3-5 分钟      │    │ · 排序筛选       │    │ · 标题锁定       │
└──────────────────┘    └──────────────────┘    └──────────────────┘    └──────────────────┘
```

> **CEO 模式**: 总管不再从头验证每个人的数据——每个专家已经自己查过搜索量、竞品等数据。总管只做战略层面的事：去重、找相似度高的选题、检查覆盖度是否全面、排序筛选。

### 信息扩散与回收

这是整个过程中选题数量的变化：

```
种子词 (1个)
    ↓ 扩散到 6-8 个 Agent
30-50 个原始选题 (每人 5-8 个，每人已自查数据)
    ↓ 总管去重合并 + 相似度分析
15-20 个独立选题
    ↓ 补充验证 + 排序
5-10 个已验证选题 (最终产出)
    ↓ Decision Brief + 创作包
Top 1-3 可直接开写的方向
```

关键点：
- **扩散阶段**：追求多样性，越发散越好。每个专家在提出选题的同时已经自己验证了搜索量数据
- **回收阶段**：总管做的是"战略决策"而非"从头验证"——去重、排序、补充缺失数据
- **产出阶段**：不只给方向，还给"决策简报"和"创作包"，可以直接开始写文章

### 每个选题标注什么

- **哪些 Agent 发现了它** — 多人共识 = 更可靠
- **各 Agent 的证据** — 不同角度的支撑数据
- **推荐内容类型** — Tutorial / List / Roundup
- **DataForSEO 验证数据** — 搜索量、CPC、竞争度（每个 Agent 已自行验证）
- **共识度分数** — 发现该选题的 Agent 数 / 总 Agent 数

### 决策简报 (Decision Brief)

除了完整报告，系统还会为 **Top 1-3 个方向** 生成一份决策简报。这是你做决策最需要看的：

---

#### 方向 #1: "Best AI UGC Ad Generators in 2026: Top 8 Tested"

| 问题 | 回答 |
|------|------|
| **为什么值得写？** | 月搜索量 8,100 且持续上升，竞品内容停留在 2025 版本 |
| **为什么现在写？** | 近 30 天搜索量增长 40%，竞品尚未更新 |
| **主要风险** | 中等竞争度，但 alici.ai 有产品差异化优势 |
| **推荐下一步** | 用 blog-list-writer 写，约 5,500 词，重点做实测方法论 |

---

每个 Top 方向还配有一个"创作包"（brief + 大纲 + Writer 启动 Prompt），可以直接交给 Writer 开始写，不需要再额外做调研。

## 与现有工具的关系

Team Scout **不替代**现有工具，而是在上层增加团队研究能力：

```
agent-team-scout (新)
  ↓ 6-8 个 Agent 并行研究 + 各自 DataForSEO 自验证
  ↓ 总管: 去重 + 相似度分析 + 排序
  ↓ 补充验证 (仅补充未验证的)
  ↓ 调用
growth-topic-scout (现有)
  ↓ Title Lock + AEO 评分
  ↓ 输出
Direction 对象 + Decision Brief + 创作包
  ↓ 创作包可直接喂给 Writer
Writer → Editor → 发布
```

核心价值：
- 每个 Agent 自带数据验证（不再等总管集中验证）
- growth-topic-scout 做**补充验证 + Title Lock**
- agent-team-scout 做**多视角发现 + 战略决策**
- 输出不只是方向列表，还有**决策简报**和**创作包**，可直接开写

## 成本与效率预估

| 指标 | 当前 Scout | Team Scout |
|------|-----------|------------|
| Token 消耗 | ~1x | ~6-8x |
| 时间 | 45-60 min (串行) | 10-15 min (并行) |
| 选题数量 | 2-3 个 | 5-10 个 |
| 多样性 | 中 | 高 |
| DataForSEO 费用 | ~$0.47 | ~$0.70 |
| 数据验证方式 | 集中验证 | 分布式 (每人自验证) + 总管补充 |

关键点：
- **Token 消耗增加但时间缩短** — 因为 6-8 个 Agent 并行工作
- **DataForSEO 费用略增但数据更可靠** — 费用分散到每个 Agent (~$0.53) + 总管补充 (~$0.17)。每个专家的选题都有数据支撑，而非只有 Top 15-20 被验证
- **性价比高** — 多 5-8x 的选题产出，仅多 ~$0.23 的外部 API 费用

## 使用场景

### 最适合 Team Scout 的场景

| 场景 | 为什么适合 | 示例 |
|------|-----------|------|
| **进入新领域** | 需要全景扫描，了解领域全貌 | "我们想开始写 AI headshots 方向的内容" |
| **季度/月度选题规划** | 一次性产出大量候选选题 | "帮我规划下个月的 5-8 篇文章方向" |
| **发现竞品盲区** | 多角色视角更容易发现竞品没覆盖的角度 | "invideo 和 heygen 都没写什么？" |
| **测试新的用户分群** | Persona 视角能发现不同用户群的需求差异 | "企业用户和个人创作者关注什么不同？" |

### 不适合 Team Scout 的场景

| 场景 | 推荐工具 |
|------|---------|
| 已确定方向，只需验证数据 | growth-topic-scout (Mode D1/D2) |
| 快速洗稿一篇竞品文章 | smart-launcher 全自动模式 |
| 单个关键词的深度分析 | growth-topic-scout (Mode B) |

每次运行 Team Scout，会在以下位置产出一组文件：

```
/research 竞品分析/team-research/YYYY-MM-DD-{seed-slug}/
├── 00-research-charter.json      ← 研究合同（记录你的选择，执行中不可改）
├── 01-agent-findings/            ← 每个 Agent 的原始发现（含自验证数据）
│   ├── topic-researcher.json
│   ├── content-strategist.json
│   ├── market-analyst.json
│   ├── prompt-engineer.json      (如启用)
│   ├── brand-specialist.json     (如启用)
│   ├── creator-persona-1.json
│   └── creator-persona-2.json
├── 02-team-research-report.md    ← 人类可读综合报告 ⭐ (你主要看这个)
├── 03-team-directions.json       ← Direction 对象 (给 Writer 用)
├── 04-agent-contributions.json   ← Agent 贡献追踪
├── 05-diversity-analysis.md      ← 多样性分析报告（含相似度矩阵 + 覆盖矩阵）
├── 06-decision-brief.md          ← 决策简报 ⭐ (Top 1-3 方向的决策信息)
└── 07-handoff-pack/              ← 创作包 (Top 方向可直接开写)
    ├── D01-brief.md               # 方向详情 + 写作指南
    ├── D01-outline.md             # 完整文章大纲
    ├── D01-prompt-kit.md          # 可直接喂给 Writer 的 Prompt
    └── ...
```

你主要关注两个文件：
- **`06-decision-brief.md`** — 快速了解 Top 1-3 方向的核心决策信息（为什么值得/为什么现在/风险/下一步）
- **`02-team-research-report.md`** — 完整报告，包含：
  - 执行摘要 (3-5 句话)
  - Agent 阵容与各自贡献
  - 最终 5-10 个选题的详细卡片
  - 多样性分析（含相似度矩阵和覆盖度）
  - 单一 Agent 独家发现（可能被低估但有价值的选题）

## 常见问题

**Q: 和现有的 seed mode v2 (Mode D2) 有什么区别？**

A: Mode D2 是一个 Agent 使用多种策略（种子交叉、Persona 轮换、SERP 空白）来增加多样性。Team Scout 是多个独立 Agent 各自研究，天然产生多样性。前者是一个人用多种方法，后者是多个人各用自己的方法。

**Q: 会不会太贵？**

A: Token 消耗约 6-8x，但外部 API 费用仅增加 ~$0.50。考虑到产出 5-10 个选题（vs 2-3 个），单个选题的成本其实差不多。

**Q: 什么时候能用？**

A: 目前处于策划阶段。本文档是概念设计 v1.1（吸收了 GPT-5 Pro PRD 的优秀理念），配套的技术规范 (`AGENT-TEAM-SCOUT-SKILL-SPEC.md` v1.1) 已同步更新。实现阶段将在概念验证通过后开始。

**Q: 能用在其他领域吗？**

A: 可以。Agent 阵容是智能推荐的，不是硬编码的。换一个种子词（如 "AI headshots"、"SaaS pricing page"），系统会推荐完全不同的 Agent 组合和 Persona。本文档以 AI UGC Ads 为示例仅为说明方便。
