### 3.1 Pillar-Cluster 主题集群 🆕

```
Pillar Page (支柱页 - 综合性指南)
├── Cluster 1: AI Image Generation (集群 1)
│   ├── Best AI Image Generators (榜单文章)
│   ├── AI Image Prompts Guide (教程文章)
│   ├── Brand Visual Consistency (指南文章)
│   └── AI Image for Marketing (应用文章)
│
├── Cluster 2: AI Video Creation (集群 2)
│   ├── Best AI Video Tools (榜单文章)
│   ├── AI Video for Marketing (应用文章)
│   ├── Thumbnail Optimization (教程文章)
│   └── Video Prompt Engineering (技术文章)
│
└── Cluster 3: AI Marketing Automation (集群 3)
    ├── AI Marketing Tools (榜单文章)
    ├── AI Content Strategy (指南文章)
    ├── AI Analytics Tools (技术文章)
    └── AI Workflow Automation (教程文章)
```

**内部链接规则**:
1. **集群页 → 支柱页**: 每篇集群文章必须链接回其支柱页（通常在导言或结论）
2. **支柱页 → 集群页**: 支柱页必须链接到所有相关集群页（通常在相关章节）
3. **集群内互链**: 同集群内的文章可相互链接（使用具体锚文本）
4. **跨集群链接**: 相关主题可跨集群链接（需语义相关）

**效果验证**:
- HireGrowth 数据: 集群内容驱动 30% 更多有机流量
- 排名保持时间长 2.5 倍

### 3.2 F-Pattern 内容结构 🆕

基于眼动追踪研究，用户阅读模式呈 F 形：

```
┌─────────────────────────────────────────────────┐
│ ████████████████████████████████████████████████ │  ← 顶部横向扫描
│ 标题 + AIDA 开篇 (用户必读区域)                   │  (停留时间最长)
├─────────────────────────────────────────────────┤
│ ████████████████████                            │  ← 次级横向扫描
│ Quick Answer section (40-60 词直答)              │  (快速获取答案)
├─────────────────────────────────────────────────┤
│ ██ H2: Section Title                            │
│ ██ [40-60 词段落起始]                            │  ← 垂直扫描
│ ██                                              │  (只读左侧开头)
│ ██ H2: Section Title                            │
│ ██ [40-60 词段落起始]                            │
│ ██                                              │
│ ██ H2: Section Title                            │
│ ██ [40-60 词段落起始]                            │
└─────────────────────────────────────────────────┘
```

**Semrush 验证**: F-Pattern 优化带来 **64% 流量增长**

**实施要点**:
1. **前 2 行黄金区**: 最重要信息放在标题 + AIDA 开篇
2. **左侧边缘优化**: H2/H3 标题必须清晰描述内容
3. **段落起始强化**: 每段首句 = 迷你 Topic Sentence
4. **视觉层次分明**: 标题、粗体、列表增强可扫描性

## 四、AEO 优化框架

### 4.1 Citable Block 系统

**目标**: 让 AI 引擎 (ChatGPT, Perplexity, Claude) 轻松提取和引用

**格式规范**:
```markdown
<!-- CITABLE_BLOCK: [简短标签] -->
[40-80 词的独立答案，包含具体数据和关键结论。必须能脱离上下文独立理解。]
<!-- /CITABLE_BLOCK -->
```

**分布策略**:
| 位置 | 数量 | 作用 |
|------|------|------|
| 开篇/背景 | 1 个 | 设定核心问题答案 |
| 主体章节 | 2-3 个 | 关键洞察 + 数据支撑 |
| 结论/要点 | 1 个 | 可操作建议 |
| **总计** | **3-5 个** | AI 引用优化 |

**示例**:
```markdown
<!-- CITABLE_BLOCK: AI Marketing Adoption 2024 -->
According to McKinsey's 2024 State of AI report, AI adoption in marketing
functions jumped to 72% in 2024, with early adopters reporting 40-60%
productivity gains. Content creation and social media management are the
two most common use cases, accounting for 68% of AI marketing deployments.
<!-- /CITABLE_BLOCK -->
```

### 4.2 Answer-First 结构 🆕

**HubSpot 最佳实践**: "Lead sections with 40-60 word direct answers"

| 元素 | 字数 | 位置 | 作用 | 示例 |
|------|------|------|------|------|
| **Direct Answer** | 40-60 词 | 每节开头 | LLM 提取目标 | "The best AI marketing tools in 2026 include..." |
| **Supporting Data** | 2-3 句 | 答案后 | 可信度验证 | "According to Gartner, 73% of marketers..." |
| **Contextual Detail** | 按需 | 支撑部分 | 深度信息 | 具体功能、定价、使用场景 |

**实施模板**:
```markdown
## H2: [Section Title]

[40-60 词直接答案，回答标题隐含问题]

[2-3 句支撑数据，来自权威来源]

[详细展开内容...]
```

### 4.3 Schema 标记优先级 🆕

基于 HubSpot 建议的实施顺序：

## 五、选题决策框架 (Ahrefs + AliciBlog 模型)

### 5.1 六维度评估模型 ⬆️

整合 Ahrefs SEO 内容策略 + AliciBlog 定制维度：

```python
def evaluate_topic(topic):
    scores = {
        # Ahrefs 三维度模型
        'business_potential': assess_business_value(topic),      # 1-10
          → 评估: 关键词对 alici.ai 的商业价值

        'traffic_potential': assess_traffic_potential(topic),    # 1-10
          → 评估: Traffic Potential (非单纯搜索量)

        'ranking_potential': assess_ranking_difficulty(topic),   # 1-10
          → 评估: 反向链接需求、竞争难度、资源可行性

        # AliciBlog 定制维度
        'marketing_orientation': assess_marketing_fit(topic),    # 1-10
          → 评估: 是否关注品牌/营销/内容创作场景

        'product_integration': assess_product_mapping(topic),    # 1-10
          → 评估: 是否能自然融入 alici.ai 产品

        'agent_advantage': assess_agent_showcase(topic),         # 1-10
          → 评估: 是否能展示 Agent 工作流优势
    }

    # 加权计算 (总分 100)
    weighted_score = (
        scores['business_potential'] * 0.20 +      # 20%
        scores['traffic_potential'] * 0.15 +       # 15%
        scores['ranking_potential'] * 0.10 +       # 10%
        scores['marketing_orientation'] * 0.25 +   # 25%
        scores['product_integration'] * 0.20 +     # 20%
        scores['agent_advantage'] * 0.10           # 10%
    ) * 10  # 转换为 0-100 分

    return weighted_score
```

### 5.2 自动选题阈值

| Weighted Score | 分级 | 动作 | 等待时间 |
|----------------|------|------|----------|
| **>= 70** | 高分 | 自动选择 | 0 分钟 |
| **50-69** | 中分 | 等待确认 | 3 分钟超时 |
| **< 50** | 低分 | 不推荐 | - |

**自动选题规则** (v1.0 保留 + v2.0 增强):
```python
# 条件 1: 高分营销相关选题
if weighted_score >= 70:
    → 自动选择

# 条件 2: 用户明确授权方向

    → 自动选择

# 条件 3: 超时后自动选择

```

### 5.3 选题方向清单

**✅ 优先选择的主题**:
- AI 营销工具 (marketing tools, content creation, social media)
- AI 视觉内容 (image generation, video creation, thumbnail design)
- AI 工作流优化 (prompt engineering, workflow automation)
- 品牌视觉提升 (brand consistency, visual quality)
- 创作者增长 (YouTube growth, viral content, CTR optimization)

**⚠️ 谨慎选择的主题**:
- 通用 AI 工具对比（除非有明确的视觉内容角度）
- 纯技术教程（除非与视觉 AI 相关）
- 新闻类内容（时效性短，ROI 低）

**❌ 不选择的主题**:
- 与视觉内容/营销无关的 AI 话题
- 竞品直接产品对比（避免负面竞争）
- 需要专业技术知识的深度技术文章

## 六、E-E-A-T 权威信号框架 ⬆️

### 6.1 四维度强化实施

| 维度 | 实现方式 | 检查项 | 示例 |
|------|----------|--------|------|

| **Authority** | 外部引用、数据来源、行业认可 | ✓ 3+ 权威来源 | McKinsey, Gartner, Semrush, HubSpot |
| **Trust** | 更新日期、透明局限性、纠错机制 | ✓ date + last_updated | "Last updated: 2026-01-17" |

### 6.2 引用信号强化 🆕

**核心数据**: HubSpot - "Content including citations, quotes, and statistics is 30-40% more visible in AI search results"

**必备引用类型**:
| 类型 | 来源示例 | 最低数量 |
|------|----------|----------|
| **行业报告** | McKinsey, Gartner, Forrester | 1-2 个 |
| **平台数据** | Semrush, Ahrefs, HubSpot | 2-3 个 |
| **学术研究** | 需注明来源和发布年份 | 可选 |
| **官方文档** | 产品官网、API 文档 | 按需 |
| **总计** | - | **3-5 个外部引用** |

**实施规范**:
```markdown

in marketing jumped to 72%...
```

```python
def calculate_citation_density(article_word_count, citation_count):
```

## 十一、洗稿模式内容哲学 (v2.2 NEW) ⭐

> 洗稿模式的核心原则和执行标准

### 11.1 洗稿模式定义

**洗稿 vs 参考**:

| 维度 | 洗稿模式 | 参考模式 |
|------|----------|----------|
| **内容保留** | 80%+ 保留原内容 | 作为起点，可扩展 |
| **结构** | 保留原结构 | 可重组 |
| **新增内容** | 禁止新增工具/场景 | 允许扩展 |
| **品牌替换** | 替换为 Alici AI | 按需植入 |
| **验证严格度** | 严格 (BLOCKING) | 宽松 (WARNING) |

### 11.2 洗稿模式六大原则

| 原则 | 规则 | 验证级别 |
|------|------|----------|
| **1. Key Takeaways 前置** | H1 后 500 字符内必须出现 | ⛔ BLOCKING |
| **2. Reframe 开篇** | Tool Showdown 强制 P4 模式 | ⛔ BLOCKING |
| **3. Source Attribution** | 必须有专门章节 + 披露声明 | ⛔ BLOCKING |
| **4. 无虚假声明** | 所有数据必须有来源 | ⛔ BLOCKING |
| **5. L4 整合者定位** | 不贬低竞品，定位为整合者 | ⚠️ WARNING |
| **6. 引用密度** | Tool Showdown ≥5/千字 | ⚠️ WARNING |

### 11.3 L4 Showdown Integrator 定位

**核心理念**: 在竞品对决中，alici.ai 不是竞品之一，而是整合者

**模板**:
```markdown
But here's the thing: **You don't have to pick just one.**

[alici.ai] gives you access to [Tool A], [Tool B], and more—
all in one platform. No signup chaos, no switching tabs.

> [CTA: Try all models free →]
```

**必须包含**:
- ✅ "don't have to pick" 或等效表述
- ✅ "one platform" 或 "single platform"
- ✅ 整合者定位，非竞争者

**禁止包含**:
- ❌ "alici.ai is the best" (自称最好)
- ❌ "better than [competitor]" (贬低竞品)
- ❌ "beats" (击败)
- ❌ "#1 tool" (排名第一)

### 11.4 洗稿模式验证流程

```python
def validate_rewrite_article(draft, source_features, intent):
    """
    洗稿模式验证函数
    """
    errors = []

    # 1. Key Takeaways 位置检查
    h1_pos = find_h1_position(draft)
    kt_pos = find_key_takeaways_position(draft)
    if kt_pos - h1_pos > 500:
        errors.append({
            "type": "BLOCKING",
            "message": "Key Takeaways 必须在 H1 后 500 字符内"
        })

    # 2. 开篇模式检查
    opening = extract_opening(draft)
    if not is_reframe_pattern(opening):
        errors.append({
            "type": "BLOCKING",
            "message": "洗稿模式必须使用 Reframe (P4) 开篇"
        })

    # 3. Source Attribution 检查
    if "About This Comparison" not in draft:
        errors.append({
            "type": "BLOCKING",
            "message": "缺少 Source Attribution 章节"
        })

    # 4. 虚假声明检查
    claim_errors = validate_claim_accuracy(draft)
    errors.extend(claim_errors)

    # 5. L4 定位检查
    if contains_self_promotion(draft):
        errors.append({
            "type": "WARNING",
            "message": "检测到自我推广语言，建议使用 L4 整合者定位"
        })

    # 6. 引用密度检查
    density = calculate_citation_density(draft)
    if density < 5:
        errors.append({
            "type": "WARNING",
            "message": f"引用密度 {density}/千字 低于目标 5/千字"
        })

    return errors
```

### 11.5 哲学总结

**洗稿模式的核心哲学**:

1. **诚实 > 营销**: 来源归属比营销话术更重要
2. **整合者 > 竞争者**: 定位为帮助用户，而非打败竞品
3. **结构化 > 创意**: 遵循验证过的模板比创新更重要
4. **验证 > 速度**: 通过验证比快速发布更重要

## 使用说明

### 对于 Topic Scout
1. 生成选题时，参考"选题决策框架"自动评分
2. 使用六维度模型 (Ahrefs + AliciBlog) 计算 Weighted Score
3. 满足自动确认条件时（>= 70），无需等待用户，直接执行

### 对于 Content Writer
1. 内容生成时，遵循"内容定位原则"自然融入产品
2. 应用 AIDA 开篇 + Answer-First 结构
3. 分布 3-5 个 Citable Blocks
4. 标题/URL/Meta 包含年份 (2026)
5. 建立内部链接（Pillar + Cluster）

### 对于 AEO Analyzer
1. 评分后，按"质量标准"决定是否需要改进
2. 首次 >= 75 直接通过
3. 首次 < 75 运行 auto-improver（最多 3 轮）
4. 3 轮后仍 < 75 标记 MANUAL_REVIEW

### 对于 Auto-Improver
1. 优先修复 M1 (结构可解析性) 问题
2. 强化 M3 (E-E-A-T 信号)
3. 确保每次改进 +3 分以上
4. 最多 3 轮迭代
