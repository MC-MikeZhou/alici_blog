# Iteration Strategy v3.2

Context:
- Canonical v3 draft has passed validator.
- KPI priority is organic traffic growth.
- Benchmark baseline comes from InVideo, Higgsfield, and OpusClip sample analysis.

## Strategic Objective

Move from "single strong tutorial" to "search cluster with evidence-backed authority":
1. Increase query coverage breadth.
2. Increase citation trust via measurable proof.
3. Increase SERP capture across how-to, template, and comparison intents.

## Version Plan

## V3.1 (Structure and Retrieval Priority)

Goal:
- Improve discoverability and answer-engine extractability without changing core workflow.

### Work items

|---|---|---|---|---|

- FAQ count >= 14 and all questions intent-tagged.
- CITABLE_BLOCK count >= 8 with >= 4 distinct types.
- At least 1 comparison table with explicit criteria.
- Internal links >= 4 contextual links.

## Measurement Framework

Primary KPI (locked): organic growth.

## Leading indicators

1. Impressions growth for target and variant queries.
2. FAQ query entry coverage.
3. Non-brand click share growth.

## Quality indicators

1. Validator status remains PASS after each update.
2. CITABLE_BLOCK extractability checks pass (standalone readability).
3. Evidence freshness age < 90 days for version-sensitive claims.

## Execution Cadence

Weekly:
1. One content experiment (hook/section order/proof placement).
2. One evidence update batch (new model/version signals).
3. One internal-link review pass.

Monthly:
1. Re-score competitor matrix.
2. Re-rank backlog by measured demand.
3. Promote one P1/P2 item to active sprint.

## Dependencies and Risks

Dependencies:
- Reliable demand data pull (DataForSEO or equivalent)
- Experiment run logs and result normalization
- Editorial bandwidth for satellite pages

Risks and mitigations:
- Risk: model/version claims decay quickly.
  - Mitigation: mandatory changelog and monthly refresh checkpoint.
- Risk: breadth increases but authority remains weak.
  - Mitigation: enforce proof-first updates before adding new sections.
- Risk: effort spread too thin across many pages.
  - Mitigation: sequence by intent value: canonical -> template vault -> alternatives showdown.

## Implementation Order (locked)

1. Execute V3.1-1 through V3.1-5.
2. Validate PASS + quality thresholds.
3. Execute V3.2-1 before satellite publishing.
4. Publish satellites and link graph.
5. Run monthly re-score and backlog reprioritization.
