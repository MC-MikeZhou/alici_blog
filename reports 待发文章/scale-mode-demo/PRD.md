# PRD - Scale Mode (批量化重构)

> 版本: v1.0
> 日期: 2026-01-24
> 负责人: Hans / Sam / Dancy

## 1. 背景与问题

AliciBlog 已形成稳定的内容工厂体系（smart-launcher 双轨、Writer → Editor → AEO → 竞品验证 → Framer），但随着功能演进，存在以下问题：

- 规范与版本分散：规则散落在多个 Skill 与文档中，统一性不足。
- 批量执行与回溯弱：缺乏标准化“批量重构”机制，无法稳定复用与复盘。
- 质量门槛维护成本上升：长文质量、链接规范、版本继承的人工检查成本高。

## 2. 目标

- 建立 Scale Mode：面向“批量化重构/改写”的标准流程与执行机制。
- 统一规范：版本继承、链接规则、标题/开篇/引用标准一致化。
- 可追踪与可回滚：每次批量执行生成 manifest 与 summary。
- “双线并行”：高质量原创 + 批量重构并行推进。

## 3. 非目标

- 不重写全部 Skill；只对批量重构所需链路做结构化升级。
- 不改变总体质量门槛（AEO ≥ 75、竞品验证 PASS/FAIL）。
- 不引入独立平台级服务。

## 4. 用户与场景

- 角色：内容负责人、运营编辑、自动化维护者。
- 场景：
  - 批量升级旧文到新规范（年份、结构、CTA、引用）。
  - 批量洗稿/改写竞品内容（基于 InVideo 高质量内容库）。
  - 批量统一输出结构（reports、assets、manifest）。

## 5. 功能范围

### 5.1 批量重构引擎

- 输入：URL 列表 / report 目录列表 / topic 清单
- 执行：队列/并行 + 失败重试 + 自动记录
- 输出：
  - 00-batch-manifest.json（任务清单 + 状态）
  - 00-batch-summary.md（汇总与结果）

### 5.2 规则与版本治理

- 版本继承：保留 E-E-A-T 保护块内容
- 链接规范：所有链接无需登录可访问
- 标题/开篇/引用校验：与 Editor 校验规则一致

### 5.3 质量门禁

- AEO ≥ 75（低于阈值自动改进）
- 竞品验证 PASS/FAIL
- 输出结构一致性校验

## 6. 质量策略（双线并行）

- 高质量原创：Hans + Dancy 负责，追求深度与品牌权威。
- 批量重构：Sam 负责，规模化产出，保证最低质量线。

## 7. 成功指标

- 批量重构完成率 ≥ 95%
- AEO 达标率 ≥ 90%
- 输出结构一致性 ≥ 98%
- 人工修复成本下降 ≥ 40%

## 8. 里程碑

- Phase 0：现有内容盘点 + 规则梳理
- Phase 1：重构规则集设计 + 链接映射表
- Phase 2：Scale Mode 批量执行流程落地
- Phase 3：小规模试点（10-20 篇）
- Phase 4：全量执行 + 复盘

## 9. 风险与应对

- 误判导致内容退化 → dry-run + diff + 小批次验证
- 版本继承失效 → 强制保护块校验
- 批量执行 API 限流 → 并行限速 + 重试策略

## 10. 交付物

- Scale Mode 批量重构流程
- 规则与校验规范（版本/链接/结构）
- 批量执行 manifest + summary 模板
- 试点报告 + 全量执行报告
